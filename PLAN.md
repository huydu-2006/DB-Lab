# Plan

Build the `backend/` REST API using **Python 3.12 + FastAPI** connected to a **Microsoft SQL Server** database, and integrate **Clerk + Google OAuth** authentication across the React frontend and FastAPI backend to replace the mock data in [data.ts](file:///d:/ICT-K69/20261%20semester/Database%20lab/Final%20project/DB-Lab/frontend/src/lib/data.ts) and stubbed auth in [auth.ts](file:///d:/ICT-K69/20261%20semester/Database%20lab/Final%20project/DB-Lab/frontend/src/lib/auth.ts).

> **Requirement change (2026-11-09):** the database was switched from **MySQL 8.0+ (InnoDB)** to **Microsoft SQL Server** (Express 2025 local instance). All schema, driver, locking, and documentation work below reflects SQL Server / T-SQL.

## Scope

- **In:**
  - **SQL Server Schema & Triggers (`backend/sql/`):** Normalized T-SQL DDL for `USERS`, `FIELDS`, `PRICING_RULES`, `BOOKINGS`, `SERVICES`, `BOOKING_SERVICES`, `PAYMENTS`, and `MAINTENANCE_LOGS`, including `CHECK` constraints (also replacing MySQL ENUM/SET domains), `AFTER INSERT`/`AFTER UPDATE` triggers with `ROLLBACK TRANSACTION; THROW 50001` to block overlapping time slots, computed columns for invoice totals, and seed data for the 8 stadium pitches.
  - **Python 3.12 + FastAPI Backend (`backend/app/`):** Clerk RS256 JWT/JWKS authentication & user synchronization (`clerk_user_id` → `USERS`), RBAC dependencies (`CUSTOMER`, `STAFF`, `ADMIN`), ACID transactional booking/service/payment endpoints (`UPDLOCK, HOLDLOCK` locking replaces MySQL `FOR UPDATE`), and SQL analytical reports.
  - **React + Clerk Frontend (`frontend/src/`):** `@clerk/clerk-react` integration with Google OAuth sign-in in [Login.tsx](file:///d:/ICT-K69/20261%20semester/Database%20lab/Final%20project/DB-Lab/frontend/src/pages/Login.tsx), typed API client (`frontend/src/lib/api.ts`), live pitch/slot/booking integration in [Dashboard.tsx](file:///d:/ICT-K69/20261%20semester/Database%20lab/Final%20project/DB-Lab/frontend/src/pages/Dashboard.tsx), [BookingDialog.tsx](file:///d:/ICT-K69/20261%20semester/Database%20lab/Final%20project/DB-Lab/frontend/src/components/BookingDialog.tsx), and [MyBookings.tsx](file:///d:/ICT-K69/20261%20semester/Database%20lab/Final%20project/DB-Lab/frontend/src/components/MyBookings.tsx), plus Staff/Admin management & revenue views.
  - **Testing:** `pytest` backend test suite (including overlap-trigger and transaction rollback verification) and frontend unit tests ([booking.test.ts](file:///d:/ICT-K69/20261%20semester/Database%20lab/Final%20project/DB-Lab/frontend/src/lib/booking.test.ts), [format.test.ts](file:///d:/ICT-K69/20261%20semester/Database%20lab/Final%20project/DB-Lab/frontend/src/lib/format.test.ts)).
- **Out:**
  - External payment gateway merchant settlement (deposits and full payments are recorded directly in the SQL Server `PAYMENTS` table).
  - Native mobile applications.
